# PhantomGeneration
## Evolution through Cookin
### Idea
The idea of using code to produce code always fascinated me. Go back into the days of the 70s and 60s. Back when binary or machine code was common developer work. Then Pascal, Fortran, and C came along. Allowing one developer to produce the work of 10 developers. One developer mastering machine code by leveraging languages like C.

My experiment. Craft a code gen project that explores the concept of rust code that produces rust code.

*My method*:

> Create a framework that is an language and specification unto itself. It compiles rust to rust, DSL and other templates into rust code. It follows the traditional path of a language creation, but let's the vanilla Rust compilier do all the compiling. Using rust features to produce rust. When reaching immediate representation stage it goes back up compounding the reach of the code into greater amounts.
\
Its ambitious, but its sure fun to engage and create with. I am learning different disciplines to do this work. In other words, I don't know what I am doing, as it is brand new, but I am sure going to get messy and do something for myself.

Its a journey. But I will see for what it is. To satisfy the curiosity and dreamscape I have in my head. Perhaps I will get lost. Maybe come back around. Camp for a while before exploring further. Evolutionary discovery.

That maybe, perhaps it will, compound upon itself and grow.

### Why Cooking

The initial idea is to make it like cooking. You have materials, you have tools and you apply cooking in different ways to create recipe.

What if you could take food to make other food.

I tend to cook large batches. Like cook hamburger for pasta, but then use the leftovers from the extra hamburger to make home made enchilada the next day. It adds very little time to cook the extra hamburger. But it saves time the next day when making the enchilada. Now scale this concept up.

**Digital Advantage**

Now instead of limited quantities, you cook the hamburger its done. What's great, is since its programming, and you scripted every action. Its very little time to do variation on that hamburger. Add spices that go well with pasta. I am not Italian, but I do my best gander at using Italian seasoning. Then use other spices for the enchilada dish. And perhaps you alter how the hamburger is cooked. But this digital space compounds such actions because it is all scripted.

I take this idea from bash scripting. I experimented automating every day tasks with some bash. And it was like magic. Exhilarating.

Now here comes the branching.

You combine hamburger with noodles. Now you have the option of many different types of Italian dishes opening up. You build more variations of dishes and realize macaroni is not that far away. So you add and remove some things from the stack. And you get a cheap meal with high quality items. Saving time. Simply because it is a digital space.

The API I am going for will mimic cooking. Its friendly to my mind because I love the time I take to cook for myself. Its relaxing and benefits from coding while combining the art aspect. I want to make this experience like cooking. You are chief in a home kitchen. And you are expanding to a formal chief kitchen. And instead of workers you have automated machines making your recipes to scale.
